- Partition key: required; DynamoDB hashes it to distribute data.
- Sort key: optional; with the partition key, it allows multiple items and ordered/range queries.
- Same partition key groups items logically. DynamoDB manages their physical storage.
- Poor key design can create hot partitions and throttling.

> DynamoDB hashes the partition key to distribute data; the sort key orders items with the same partition
key and supports range queries.
