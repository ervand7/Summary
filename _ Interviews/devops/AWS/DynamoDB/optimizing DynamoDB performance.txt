## DynamoDB performance

- Design keys for access patterns; use `Query` instead of `Scan`.
- Avoid hot partition keys. Denormalize when it reduces reads.
- Choose on-demand for variable traffic; provisioned with auto scaling for predictable traffic.
- Add DAX for frequent, read-heavy workloads where eventual consistency is acceptable.

> Fix the data model first, tune capacity next, and add caching only if needed.
