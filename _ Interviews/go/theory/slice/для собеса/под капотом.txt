`slice` is a descriptor over an array, not a container itself.

```
type slice struct {
    ptr *T   // Pointer to the underlying array
    len int  // Current length
    cap int  // Capacity
}
```

- A slice references an underlying array
- Multiple slices can reference the same underlying array
- Changes through one slice can be visible through another

## Slice operations

### 1) Slicing
```
s[:n]  // len = n, cap remains unchanged
s[n:]  // len decreases, cap = cap - n
```

📌 No new underlying array is allocated.

### 2) append
```
append(s, x)
```

- ✅ If `len+1 <= cap`
  - Writes to the same underlying array
  - Returns a new slice header with updated length
- ✅ If `len+1 > cap`
  - Allocates a new underlying array
  - Copies existing elements
  - Returns a new slice referencing the new array

📌 Always use the returned slice if you need the updated length and elements.

## Can you store a pointer to a slice element?
Yes, even if `append` causes reallocation:

- `append` may allocate a new underlying array
- Existing pointers remain valid and reference the old array
- The garbage collector keeps the old array alive while references exist

## Common mistakes (top 3)

1. Ignoring the result of `append`
2. Unexpected modifications due to shared underlying arrays
3. Large `cap` allowing `append` to modify data shared with other slices

## Golden rule (for interviews)

> A slice is a view over an array.
> `append` reallocates the underlying array only when capacity is insufficient.
