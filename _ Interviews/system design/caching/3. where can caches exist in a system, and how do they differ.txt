1. Client cache (browser/mobile)
   - Local storage for static or user-specific data.

2. CDN / Edge (Cloudflare, CloudFront)
   - Caches static assets and HTTP responses close to users.

3. Reverse proxy (Nginx, Varnish)
   - Caches HTTP responses before reaching application servers.

4. Application cache (Go map, Ristretto)
   - Extremely fast, in-process memory.
   - Not shared across replicas, potential inconsistency.

5. Distributed cache (Redis, Memcached)
   - Shared across replicas, survives application restarts.
   - Adds network latency and infrastructure complexity.

6. Database cache (PostgreSQL shared buffers)
   - Automatically caches frequently accessed database pages.
   - Managed by the DB, limited application control.

Key takeaway:
- Closer to the client = lower latency and less downstream load.
- Local cache = fastest, but harder to keep consistent.
- Distributed cache = shared data, but additional network and operational costs.
- More cache layers = more complex invalidation.
