### 1. Synchronous
`API Gateway → Lambda → Response`

- Client waits for the result.
- Errors returned immediately.
- Caller handles retries.
- Use: REST APIs, authentication, payments.

### 2. Asynchronous
`S3 → Lambda`

- Caller doesn't wait for execution.
- AWS queues the event internally.
- Lambda automatically retries failures.
- Failed events can go to DLQ/destinations.
- Use: Notifications, image processing.

### 3. Polling (Event Source Mapping)
`SQS → Lambda`

- Lambda's event source mapping polls SQS.
- Messages are deleted after successful processing.
- Failed messages become available again after visibility timeout.
- DLQ handles repeated failures when configured.
- Use: Background workers, queue processing.

Key difference:
- Sync: Caller waits and handles retries.
- Async: Lambda manages retries.
- Polling: Event source controls redelivery.
